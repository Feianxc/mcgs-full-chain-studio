# Support

## Community support

Use GitHub Issues for reproducible bugs and generic feature requests. Before opening an issue:

1. use the latest supported version;
2. reproduce with synthetic, non-customer data;
3. run the repository validation and test commands;
4. remove local paths, credentials, project names, point tables and generated files.

This open-source project does not promise response times, on-site commissioning, project design review or compatibility with every MCGS version and device driver.

## Security and private data

Do not post vulnerabilities, credentials, customer information, `.MCP` files, screenshots of real projects, production configuration or account databases in public issues.

Use GitHub Private Vulnerability Reporting as described in [SECURITY.md](SECURITY.md). If private reporting is not enabled, contact a repository maintainer through a non-public channel without attaching sensitive data.

## Engineering boundary

Community assistance and generated output are not formal project acceptance. Users remain responsible for:

- confirming requirements against drawings and point tables;
- checking every generated mapping and alarm definition;
- performing MCGS GUI review, compilation and simulation;
- completing device, network and site commissioning;
- recording human approval before production use.
